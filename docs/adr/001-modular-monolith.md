# ADR-001：控制面采用模块化单体与端口适配器

## 状态

已接受。

## 决策

控制面以一个 FastAPI 进程交付，但内部严格分为领域层、应用层、端口、适配器和 API。领域层不依赖框架；内存与 PostgreSQL 仓储、演示与真实 Agent 执行器可以替换。

## 原因

4GB 单机不适合维护大量微服务、队列和服务发现组件。模块化单体保留清晰边界与测试能力，同时避免网络、部署和资源成本。未来只有出现明确的独立扩缩容或故障隔离需求时才拆分进程。

## 后果

- 优点：开发和部署简单；本地测试无需外部服务；业务规则不会被框架锁定。
- 代价：进程级故障仍影响整个控制面；模块边界需要静态检查和评审持续维护。
