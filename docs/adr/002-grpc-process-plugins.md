# ADR-002：插件采用独立进程与 gRPC

## 状态

已接受。

## 决策

插件以独立进程运行，通过 Unix Socket 上的 protobuf/gRPC 通信。阶段一使用 `google.protobuf.Struct` 作为版本化信封，并固定服务名和 RPC 生命周期。

## 原因

Python 动态导入虽然简单，但无法隔离崩溃和依赖冲突，也不利于 Go/Python 跨语言插件。WASM 权限模型更强，但系统运维访问、调试和 SDK 建设成本会偏离 AIOps 主线。

## 后果

- 优点：插件崩溃隔离、语言无关、可独立升级，Unix Socket 不暴露公网端口。
- 代价：需要进程管理、健康检查、协议兼容和权限声明；阶段一的 Struct 信封不如强类型消息精确。
- 演进：稳定字段形成后增加强类型 protobuf 消息，但保留服务名、生命周期与 API 版本协商。
